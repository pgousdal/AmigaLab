# AmigaLab v0.2.0 — M2 Preservation Platform

## Release overview

AmigaLab v0.2.0 closes the M2 preservation platform and establishes a stable
boundary before M3 development and museum workflows.

## Major capabilities

The release includes reproducible Debian Minimal Ansible setup; namespaced
standalone/coexistence architecture; Amiga cross-development foundations;
immutable collections and canonical metadata; preservation objects/files with
MD5, SHA-1, SHA-256, and SHA-512; provenance and append-only history;
non-destructive plans and transaction recovery; licensed-media handling;
ISO/directory/ZIP/TAR adapters; external source inspection; resumable
snapshots and change detection; mirror plans and approved HTTPS acquisition;
media analysis; Aminet hierarchy and `.readme` preservation; separately
approved imports; verification, traceability, reconciliation, repair plans;
opt-in operations and retention; SQLite FTS5 cataloging; `.readme` parsing;
local read-only web views/API; and optional Meilisearch integration.

## Architecture and guarantees

Preserved files and canonical metadata remain authoritative. SQLite,
Meilisearch, reports, and the web interface are rebuildable or read-only
derived layers. Scheduled and web operations never approve or execute plans
automatically, modify preserved content, or run torrents.

> AmigaLab v0.2.0 completes the M2 preservation platform. Preserved files and canonical metadata remain authoritative; SQLite, Meilisearch, and the web interface are rebuildable or read-only derived layers.

## Upgrade and migration notes

No destructive migration is required. Existing metadata remains readable.
Build the catalog after upgrading with `catalog-build`; optional Meilisearch
can be synchronized explicitly. Timers and the web service remain disabled by
default.

## Known limitations

- ISO support depends on optional `pycdlib`.
- Meilisearch verification is currently health/configuration oriented; full
  remote document reconciliation and broad stale-document deletion remain
  limited.
- Rich web pages remain compact server-rendered views.
- File-body serving is intentionally disabled.
- Torrent download/execution is not implemented.
- Mirror-plan and import-plan approval remain manual.
- CommodoreLab and VICE are separate future work.
